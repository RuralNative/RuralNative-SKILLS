# Seam: plan-this

## Purpose

The skill that applies the planning prefix as a fixed template. It is invoked either directly as `/plan-this <task>` by the user or via narrow delegation from an active `supervise-this` run, preserves the supplied planning workflow verbatim, places the invocation task under `## Task:`, and delegates to `/grill-with-docs`, `/to-spec`, and `/to-tickets` with `/unslop` active.

## Scope & boundaries

Owns: the content under `skills/plan-this/` — `SKILL.md`, `INSTALL.md`, `tests/`. Delegates: the planning workflow to `/grill-with-docs`, `/to-spec`, `/to-tickets`; prose quality to `/unslop` (external, not `unslopify`). The seam is a fixed-template adapter — it does not reimplement delegated skills, copy the `AIT-*` catalog, add runtime scripts, or create `.kilo/command/` entries. Installation uses the registry lane only. Invocation is limited to direct user use and narrow delegation from an active `supervise-this` run; unrelated model invocation is rejected.

## Key files & data flow

`SKILL.md` is the entry point; its frontmatter `name` is the skill identity `plan-this` and its `description` declares the explicit invocations `/plan-this <task>` and narrow delegation from an active `supervise-this` run plus delegation to `/grill-with-docs`, `/to-spec`, `/to-tickets`, and `/unslop`. The consumption paths are: direct — user runs `/plan-this <task>` → skill loads `/unslop` before the first progress update and keeps it active → runs `/grill-with-docs` → `/to-spec` → `/to-tickets` in order, substituting only the task under `## Task:` → produces specification and tickets and stops after the ELI18 summary; delegated — an active `supervise-this` run delegates planning with the same task slot → the same workflow executes → delegated completion returns the published parent specification and ticket references to the supervisor instead of ending the whole supervised run. Both paths share the single `## Task:` substitution point. The body after frontmatter equals the verbatim expected prefix with that single slot — the workflow line `Run this planning-only workflow: ` + `` `/grill-with-docs` → `/to-spec` → `/to-tickets` ``, `## Rules:` with ten bullets, the `Finish with an ELI18 **Why / What / Where / How** summary` line, and the `## Task:` slot — totaling ~21 lines including frontmatter with no wrapper sections, start markers, or separate `## Hard dependencies` / `## Rules preserved` / `## Installation` / `## Boundary` sections, and it stays byte-for-byte unchanged across both invocation paths. Hard dependencies are declared via that prefix plus the frontmatter `description`, not via a separate Hard dependencies section. `INSTALL.md` documents the registry lane `npx skills add RuralNative/RuralNative-SKILLS --skill plan-this` and the manual copy `cp -r skills/plan-this`. The registry discovery walks `skills/plan-this/` and a consumer installs by skill identity. The repo never carries its own install — `.agents/` and `skills-lock.json` are ignored. Tests live in `skills/plan-this/tests/` and encode the invariants, including a line-count bound, wrapper absence, byte-for-byte body checks, and both allowed invocation paths with rejection of unrelated invocation.

## Non-negotiables

1. **INV-1** — `SKILL.md` frontmatter `name` equals the folder name `plan-this`.
2. **INV-2** — The registry-lane command in `INSTALL.md` installs this seam as `npx skills add RuralNative/RuralNative-SKILLS --skill plan-this` with matching manual copy `cp -r skills/plan-this`; discovery text names the explicit user invocation `/plan-this <task>` and preserves the example task verbatim under `## Task:`.
3. **INV-3** — Fixed-template boundary: `SKILL.md` body after frontmatter equals the exact supplied planning prefix verbatim, including `Run this planning-only workflow: ` + `` `/grill-with-docs` → `/to-spec` → `/to-tickets` ``, the ten Rules bullets, the `Finish with an ELI18 **Why / What / Where / How** summary` line, and the single `## Task:` slot, substituting only the task text; it preserves exact domain terms, identifiers, commands `ready-for-agent`, dependency names, quotations, and technical meaning, and does not add router skills, `.kilo/command/` files, runtime scripts, or model evals, and does not contain wrapper phrases `Rules preserved`, `## Installation`, `## Boundary`, `--- start of supplied`, or `This skill is a thin fixed-template adapter`. The file totals 18–35 lines including frontmatter (~23). Mechanism: prose invariant — `SKILL.md` contains verbatim expected prefix (workflow line, ten Rules bullets, final summary line, `## Task:`) and single substitution point, with no wrapper markers and no extra machinery on disk (`scripts/`, `package.json`, `.kilo/command/`); composition test guards verbatim equality, single `## Task:`, wrapper absence, and line-count bound.
4. **INV-4** — Hard dependencies are `/unslop`, `/grill-with-docs`, `/to-spec`, `/to-tickets` with workflow order `/grill-with-docs` followed by `/to-spec` followed by `/to-tickets` and `/unslop` loaded before the first progress update and kept active throughout; hard dependencies, in order, are `/grill-with-docs`, `/to-spec`, `/to-tickets`, and `/unslop` and are declared via the workflow line and first Rules bullet plus frontmatter description, not via a separate Hard dependencies section. `/grill-with-docs`, `/to-spec`, and `/to-tickets` set `disable-model-invocation: true` and require explicit human invocation; an agent cannot traverse the chain unattended. `/unslop` carries no such lock and remains model-invocable. The skill does not silently map `/unslop` to `unslopify`; the local `unslopify` seam stays unchanged. Mechanism: composition test in `skills/plan-this/tests/` verifies dependency names appear in body and frontmatter and workflow order is preserved.
5. **INV-5** — The skill accepts two invocations and rejects others: direct user use as `/plan-this <task>` and narrow delegation from an active `supervise-this` run; unrelated model invocation is rejected. Its `description` states both allowed paths explicitly and declares rejection of unrelated invocation, and it does not introduce broad automatic triggering. Preserved rules are those ten bullets as they appear in the trimmed prefix — To-Do List covering Discovery, Decisions, Specification, Tickets, Delivery with phase updates, ticket design as independently verifiable vertical slices suitable for one worktree with blockers, affected seams, acceptance criteria, verification and parallel-safety notes, precision per token with parent context, grounded decisions following the loading order, `ready-for-agent` labels with native dependency edges, ELI18 decision question with recommendation and approval gates, and following installed skills as source of truth — plus the final ELI18 **Why / What / Where / How** summary, without requiring a separate `## Rules preserved` section in `SKILL.md`. Standalone completion stops after that summary; delegated completion returns the published parent specification and ticket references to the active supervisor instead of ending the supervised run, while the fixed-template body, task slot, dependency order, prose rules, and approval gates stay byte-for-byte unchanged. Mechanism: composition test verifies explicit invocation phrasing for both paths, rejects unrelated invocation, checks byte-for-byte body preservation, single `## Task:` slot, dependency order, and presence of preserved rule sections.
6. **INV-6** — Delegation does not create a second planning contract and its stop semantics remain narrow: the fixed-template body is the single source of planning behavior and is shared unchanged across both invocation paths, and the only difference between paths is where the final stop returns control — to the user for standalone and to the active `supervise-this` supervisor for delegated use. Mechanism: prose invariant — leaf doc explains the narrow delegation rule; `SKILL.md` body has no diff between paths; composition test guards byte-for-byte body equality, task-slot singularity, and that delegated stop returns references while standalone stop ends the run.
7. **INV-7** — Bounded-planning contract: parent specification separates in-scope behavior from out-of-scope non-goals with acceptance criteria, affected seams, structural constraints, and the smallest test-first verification plan; tickets are independently verifiable vertical slices stating behavior, blockers, affected seams, acceptance criteria, verification and parallel-safety; test design precedes implementation and rejects redundant/prose-mirroring/coverage-only tests unless a distinct risk is named. Mechanism: composition tests tagged for this invariant verify bounded scope and lean test criteria within the 18–35 line bound.
8. **INV-8** — Native dependency edges are canonical. `plan-this` creates blocked_by edges after reading each issue's database ID via `gh issue view --json databaseId`; human-readable Blocked by section remains as fallback when GitHub does not support native edges. Label state follows native blockers: open blocker → blocked without ready-for-agent; all native blockers closed → remove blocked, add unblocked + ready-for-agent. Mechanism: composition test verifies blocked_by, database ID read, fallback text, canonical native, and label transitions.
