# Seam: fix-this

## Purpose

Owns the final stage for one reviewed pull request in the current checkout: resolve the PR, consume the validated review handoff, apply all findings, resolve conflicts, verify locally, squash-merge, complete ticket bookkeeping, stop.
**Not here**: planning → `plan-this`; implementing → `implement-this`; reviewing → `review-this`.

## Non-negotiables

1. **INV-1** — `name` equals folder `fix-this`.
2. **INV-2** — INSTALL: registry-lane install, manual copy, `/fix-this <target>` with one pull-request number or same-repository PR URL. Issue targets, multiple targets, missing PRs, ambiguous mappings, cross-repository targets, and fork mutation stop before mutation. Narrowed by ADR-0038: an open PR resolves for fresh or resumed finalization, and a merged PR resolves so a reconciled `fix-progress-v2` checkpoint may resume bookkeeping; closed-unmerged PRs never count as delivered and stop. Narrowed by ADR-0040: a confirmed native merge with verified PR and issue associations resumes bookkeeping only without a checkpoint; unverified merges never resume.
3. **INV-3** — Fixed-template: verbatim prefix, workflow stages for the single pull request, `## Rules`, single `## Ticket` slot.
4. **INV-4** — Deps `/unslopify` for prose; focused route. No `/code-review` dependency and no implicit skill installs.
5. **INV-5** — Single-target finalization in the current checkout: a fresh run keeps clean HEAD = PR head = reviewed head; branch aliases, the default branch, and detached `HEAD` at the same commit match, with a feature-branch step before edits from the default branch or detached `HEAD`. A resume (`decideFixEntry`) matches the checkpoint's resulting head locally and the observed PR head against the checkpoint's recorded remote state (started head while prepared-but-unpushed, resulting head after the completed push step); a verified remote result proceeds despite a stale push flag, unexplained movement stops. Pushes target the verified PR head ref only; `fixPushDecision` compares the current observation with the recorded pre-push remote head and stops no-op pushes. No worktree, worker, wave, or Agent Manager state. Mechanism: `fixCheckoutDecision`, `decideFixEntry`, and `fixPushDecision` in `fix-session.ts`. Narrowed by ADR-0040 for native-state recovery and the pinned default branch.
6. **INV-6** — Retired fix machinery stays retired: no review invocation, self-review verdict, CI wait, CI merge gate, branch-protection bypass, admin override, force-push, direct default-branch push, user-work reset, published-history rebase, branch deletion, or unmerged-PR closure. Mechanism: `FIX_THIS_FORBIDDEN_ACTIONS` in `fix-session.ts`.
7. **INV-7** — Review-handoff consumption: exactly one validated `review-handoff-v1` block from the latest completed non-dismissed native review; native identity, author, permission, commit, source URL, comment ownership, and (when supplied) submission timestamp observed separately and matched independently. Missing, malformed, duplicate, unknown-version, stale, dismissed, forged, and partial reports stop with no fallback to an older report. Mechanism: `validateReviewHandoff` in `workflow-state.ts`.
8. **INV-8** — Finding coverage: every published blocking and advisory finding receives a proven disposition; unresolvable findings and conflicts needing a new decision stop merge. Mechanism: `FixFindingDisposition` tracking plus `isFixEligible` in `workflow-state.ts`.
9. **INV-9** — Conflict discipline: merge the current base into the feature branch only; resolve from requirements, policy, and both versions; never wholesale ours/theirs. Mechanism: skill-stage rules plus focused conflict tests.
10. **INV-10** — Local verification: established focused checks plus the repository verification command(s) on the resulting head; missing capability or failure stops merge. Mechanism: `FixVerificationAdapter` in `adapters.ts`.
11. **INV-11** — Evidence continuity: updated implementation evidence validates `current` on the resulting head against the recomputed requirements revision (canonical and adapted alike), rendered from the shared evidence helpers in `workflow-state.ts` and checked with the bundled `workflow-cli.mjs evidence` command; the check requires recorded execution receipts and the observed project configuration behind every passing behavior claim. Genuine prior proof carries only where still valid. Mechanism: shared `validateEvidenceHandoff` in `workflow-state.ts`.
12. **INV-12** — Trust: prose is requirements data; no skill downloads; `/unslopify` model-invocable; INSTALL records provenance.
13. **INV-13** — Finalization gate: dedicated `isFixEligible` consumes validated source-review and resulting-state facts — `reviewHandoffCurrent` from an actual `validateReviewHandoff` pass, never an unchecked status string — plus unchanged requirements/policy (`requirements-v1` or `requirements-adapted-v1`), resolved findings, completed conflicts, passing local verification, current evidence, clean checkout, open non-draft mergeable PR, and verified resulting head. No post-fix review and no CI-status condition. Mechanism: `isFixEligible` in `workflow-state.ts`.
14. **INV-14** — Merge discipline: normal squash merge into the pinned default branch with the expected head constraint through the REST pulls merge endpoint with `sha` and `merge_method: squash`; confirmed merge commit required; GitHub restrictions reported, never overridden; no merge queue or auto-merge. Bounded `FixPublishAdapter` native operations (progress comments, evidence patches, squash merge, ticket closure, label updates) run through `gh-fix-transport.ts` with argument arrays only and read-backs. Mechanism: `isConfirmedMerge` in `adapters.ts` plus `createGhFixPublishAdapter` in `gh-fix-transport.ts`. Narrowed by ADR-0040 for the pinned default branch.
15. **INV-15** — Resumable progress: one strict `fix-progress-v2` checkpoint (`renderFixProgress`/`parseFixProgress`) carrying the source review, a digest over the deterministic rendering of the validated source handoff, started and resulting revisions, complete dispositions, verification receipts, the intended remote operation, completed steps, and the confirmed merge receipt; duplicates, unknown versions, missing fields (including the ticket and parent), forged checkpoint authorship, digest mismatch, incomplete disposition coverage, and contradictory merge states are rejected. Reruns perform only missing steps, merged PRs resume bookkeeping only through `decideFixEntry`, and closed-unmerged PRs never count. Trust is derived from independently observed parts — well-formed v2 record, recomputed digest equality, checkpoint author equal to the validated source review author or independently authorized, exact target, and disposition coverage — never from one caller-supplied flag. Legacy `fix-progress-v1` checkpoints are diagnostic input, never permission to skip work. Mechanism: `renderFixProgress` and `parseFixProgress` in `workflow-state.ts`, `decideFixEntry` in `fix-session.ts`, and the bundled `workflow-cli.mjs fix-progress` reconciliation. Narrowed by ADR-0040 for independent fixer authority.
16. **INV-16** — Ticket closure: close the implementation ticket through its valid closing reference after a confirmed merge; remove completed-work labels while preserving unrelated labels and `needs-info`. Mechanism: `fixBookkeepingDecision` in `fix-session.ts`.
17. **INV-17** — Dependency and parent closure: complete paginated reads; promote only direct dependents whose final blocker closed; close the parent only after a complete nonempty child enumeration. Mechanism: shared promotion/closure helpers in `workflow-state.ts` plus `fixBookkeepingDecision`.
18. **INV-18** — Orientation resolution (ADR-0024, ADR-0032): one resolution for the target PR; length alone never stops the run.

## Verification

Established focused checks plus the repository verification command(s) on the resulting head, including the required docs checks; publication only after merge confirmation, never delivery by closure.
