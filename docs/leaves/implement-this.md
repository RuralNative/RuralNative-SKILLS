# Seam: implement-this

## Purpose

The skill that applies the implementation prefix as a fixed template. It is user-invoked as `/implement-this #<n>`, preserves the supplied implementation workflow verbatim, substitutes the requested issue reference in place of `Issue #0`, and delegates to `/implement` and `/code-review` with `/unslop` active.

## Scope & boundaries

Owns: the content under `skills/implement-this/` — `SKILL.md`, `INSTALL.md`, `tests/`. Delegates: the implementation workflow to `/implement` and `/code-review`; prose quality to `/unslop` (external, not `unslopify`). The seam is a fixed-template adapter — it does not reimplement delegated skills, copy the `AIT-*` catalog, add runtime scripts, or create `.kilo/command/` entries. Installation uses the registry lane only. The second slice extends shared catalog documentation established by the `plan-this` slice.

## Key files & data flow

`SKILL.md` is the entry point; its frontmatter `name` is the skill identity `implement-this` and its `description` declares the explicit invocation `/implement-this #<n>` and delegation to `/implement`, `/code-review`, `/unslop`. The body after frontmatter equals the verbatim implementation prefix with a single `Issue #0` substitution point: the worktree line `Implement the GitHub ticket in this dedicated worktree: `/implement` → `/code-review``, the authority line `Treat the ticket, its comments, and its linked parent specification as the task authority.`, the six Rules bullets, the five Start steps, the Build and verify block, and the five Review & Deliver steps with never force-push and the `## Ticket Issue #0` slot carrying exact Git commands `git branch --show-current`, `git status --short`, `git fetch origin`, `gh issue edit <n> --add-assignee @me`, `npm ci`, `npm run format && npm test && npm run lint && npx tsc --noEmit && npm run docs:check && npm run build`, `BASE=$(git merge-base origin/main HEAD)`, `git rebase origin/main`, `git push origin HEAD:main`. Hard dependencies `/implement`, `/code-review`, `/unslop` are declared via the prefix workflow order plus the frontmatter description, not a separate Hard dependencies section. The consumption path: user runs `/implement-this #<n>` → skill loads `/unslop` before the first progress update and keeps it active → runs `/implement` followed by `/code-review` in order, substituting only the issue reference in place of `Issue #0` → follows worktree checks, ticket authority, claiming, verification, documentation, review, rebase, push, and issue-closing steps per the prefix. `INSTALL.md` documents the registry lane `npx skills add RuralNative/RuralNative-SKILLS --skill implement-this` and the manual copy `cp -r skills/implement-this`. The registry discovery walks `skills/implement-this/` and a consumer installs by skill identity. The repo never carries its own install — `.agents/` and `skills-lock.json` are ignored. Tests live in `skills/implement-this/tests/` and encode the invariants. Former wrapper sections — Invocation details, Hard dependencies exposition, Rules preserved summary, Installation, and Boundary — now live only in this leaf doc, `INSTALL.md`, and the ADR, not in `SKILL.md`.

2. **INV-2** — The registry-lane command in `INSTALL.md` installs this seam as `npx skills add RuralNative/RuralNative-SKILLS --skill implement-this` with matching manual copy `cp -r skills/implement-this`; discovery text names the explicit user invocation `/implement-this #<n>` and preserves the example `Issue #100` in place of `Issue #0`.
3. **INV-3** — Fixed-template boundary: `SKILL.md` body after frontmatter equals the exact supplied implementation prefix verbatim, including the worktree line `Implement the GitHub ticket in this dedicated worktree: `/implement` → `/code-review``, the authority line `Treat the ticket, its comments, and its linked parent specification as the task authority.`, the six Rules bullets, the five Start steps, the Build and verify block, and the five Review & Deliver steps with never force-push and the `## Ticket Issue #0` slot with exact Git commands `git branch --show-current`, `git status --short`, `git fetch origin`, `gh issue edit <n> --add-assignee @me`, `npm ci`, `npm run format && npm test && npm run lint && npx tsc --noEmit && npm run docs:check && npm run build`, `BASE=$(git merge-base origin/main HEAD)`, `git rebase origin/main`, `git push origin HEAD:main`, substituting only the issue reference in place of `Issue #0`; it preserves identifiers `ready-for-agent`, `AGENTS.md`, `docs/agents/issue-tracker.md`, `Issue #0`, `/tmp/kilo`, `*.test.ts`, dependency names, quotations, and technical meaning, and does not contain wrapper phrases `Rules preserved`, `## Installation`, `## Boundary`, `--- start of supplied`, `This skill is a thin fixed-template adapter`, `## Invocation`, `## Hard dependencies` and does not add router skills, `.kilo/command/` files, runtime scripts, or model evals, totaling ~83 lines with a single `Issue #0` in body. Mechanism: prose invariant — `SKILL.md` contains the verbatim prefix and a single `Issue #0` substitution point, with no extra machinery file on disk. Wrapper phrases listed above must not appear in `SKILL.md`; the composition test guards this drift.
4. **INV-4** — Hard dependencies are `/unslop`, `/implement`, and `/code-review` with workflow order `/implement` followed by `/code-review` and `/unslop` loaded before the first progress update and kept active throughout, declared via the prefix workflow order plus frontmatter description, not a separate Hard dependencies section; hard dependencies, in order, are `/implement`, `/code-review`, and `/unslop`, following the supplied implementation prefix with never force-push and single `Issue #0` substitution. The skill does not silently map `/unslop` to `unslopify`; the local `unslopify` seam stays unchanged. Mechanism: composition test in `skills/implement-this/tests/` verifies dependency names appear in prefix and frontmatter and workflow order is preserved.
5. **INV-5** — The skill is user-invoked only via `/implement-this #<n>`; its `description` makes the explicit slash command and accepted input clear and it does not introduce broad automatic triggering. Preserved rules as they appear in the trimmed prefix include worktree checks, ticket and specification authority, dependency checks, claiming with `gh issue edit <n> --add-assignee @me`, verification with `npm run format && npm test && npm run lint && npx tsc --noEmit && npm run docs:check && npm run build`, documentation with leaf update in same commit, review via `/code-review` with `BASE=$(git merge-base origin/main HEAD)`, rebase with `git rebase origin/main`, push with `git push origin HEAD:main` and never force-push, issue comment with evidence, label removal of `ready-for-agent`, and closure with the final ELI18 Why / What / Where / How summary including commit SHA, verification results, and closed ticket link, without requiring a separate `## Rules preserved` section. Mechanism: composition test verifies explicit invocation phrasing and presence of preserved rule sections and exact Git commands as they appear in the trimmed prefix.
