# 0007 — Supervise-this workflow coordinator

Status: accepted
Date: 2026-08-19

Decision: One task-scoped coordinator skill ships with identity `supervise-this` and explicit forms `/supervise-this <task>` for a new planning run and `/supervise-this #<parent-spec>` for resume. It accepts planning model and variant plus implementation model and variant before the task or spec reference, with an optional review model and variant that defaults together to the confirmed planning selection. Partial review or missing required fields produce one ELI18 decision before any session starts. Every model name and variant is resolved through `agent_manager_models`, which accepts catalog model names and qualified provider and model identifiers; the skill contains no hard-coded model allowlist. The supervisor shows the exact resolved planning, implementation, and review selections and requires one confirmation before creating any session. An unavailable or ambiguous model or variant pauses the affected phase and never triggers a silent fallback. Planning starts as an Agent Manager local session with the confirmed planning model and variant and a delegated `plan-this` task; the skill does not change the model of the current Kilo session. Delegated planning honors all `plan-this` approval gates and returns the published specification and ticket references, and the supervisor records the resolved phase configuration in one structured parent comment before implementation so a later run can resume. Existing adapters `plan-this` and `implement-this` keep their fixed-template bodies byte-for-byte unchanged and gain a narrow delegation path from an active `supervise-this` run. GitHub issues, native dependencies, evidence comments, and commits are the durable record; Agent Manager `list` is the live-state source and `.kilo/agent-manager.json` is never edited.

Why: Planning and implementation need different model cost and quality levels, and repeating manual worktree and spec management is slow and error-prone. A coordinator that validates model choices against the live catalog, asks once for missing input, confirms the exact resolved configuration, and reuses established adapter contracts avoids copying workflows, avoids stale allowlists, and keeps the supervisor focused on coordination and model routing rather than on reimplementing planning or ticket delivery. Local planning sessions match the publish-only nature of spec work, and a single recorded parent comment makes the run resumable from GitHub even when prior Agent Manager sessions are gone.

Consequences:
- The glossary gains a `supervised run` term for the lifecycle.
- The architecture index adds the `supervise-this` seam, its leaf doc, and this ADR.
- `plan-this` and `implement-this` declaration texts are extended to allow narrow delegation from an active `supervise-this` run without changing their fixed-template bodies.
- Registry-lane discovery uses `npx skills add RuralNative/RuralNative-SKILLS --skill supervise-this` with matching folder identity.
- Follow-up slices keep the coordinator thin by owning only preflight, frontier, bounded concurrency, live-state polling, recovery, resumption, whole-spec review, and parent closure, while planning and per-ticket behavior stay in their adapters.
- Tests verify identity == folder, explicit invocation, required and optional fields, review defaulting, partial-review rejection, catalog resolution through `agent_manager_models`, qualified identifier acceptance, approval before execution, unavailable-selection pause, local planning-session routing, and the ban on silent fallback.
