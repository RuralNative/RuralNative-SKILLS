# 0007 — Supervise-this workflow coordinator

Status: accepted
Date: 2026-08-19

Decision: One task-scoped coordinator skill ships with identity `supervise-this` and explicit forms `/supervise-this <task>` for a new planning run and `/supervise-this #<parent-spec>` for resume. It accepts planning model and variant plus implementation model and variant before the task or spec reference, with an optional review model and variant that defaults together to the confirmed planning selection. Partial review or missing required fields produce one ELI18 decision before any session starts. Every model name and variant is resolved through `agent_manager_models`, which accepts catalog model names and qualified provider and model identifiers; the skill contains no hard-coded model allowlist. The supervisor shows the exact resolved planning, implementation, and review selections and requires one confirmation before creating any session. An unavailable or ambiguous model or variant pauses the affected phase and never triggers a silent fallback. Planning starts as an Agent Manager local session with the confirmed planning model and variant and a delegated `plan-this` task; the skill does not change the model of the current Kilo session. Delegated planning honors all `plan-this` approval gates and returns the published specification and ticket references, and the supervisor records the resolved phase configuration in one structured parent comment before implementation so a later run can resume. Resume (`/supervise-this #<parent-spec>`) resumes without creating a duplicate specification or duplicate child ticket, reads the newest valid structured planning, implementation, and review configuration with a missing or malformed configuration producing one ELI18 decision before any new session, reconstructs durable progress from the parent specification, child and follow-up issues, native dependencies, labels, evidence comments, commits on `origin/main`, and the newest valid phase model configuration before consulting live Agent Manager sessions and reconciles with `list` where stale or missing sessions do not erase durable progress, revalidates each recorded model through `agent_manager_models` before creating any missing session and preserves every available selection exactly without substituting the current supervisor model, pauses only phases that require an unavailable recorded model or variant with `needs-info` and asks for one replacement decision with a recommendation while an approved replacement produces a new structured parent configuration comment preserving the earlier comment as history, does not duplicate a worker for an open assigned ticket or active session, restarts implementation or follow-up worktrees with the recorded implementation model and variant and restarts final-review with the recorded review model and variant, inspects evidence before prompting any idle, waiting, retrying, or offline worker with an open issue and sends at most one focused recovery prompt in the existing selected-model session for a scoped mechanical failure with still-blocked tickets gaining `needs-info`, recording the concrete blocker, and asking one ELI18 decision while unrelated ready tickets continue and descendants remain blocked until dependencies close, creates confirmed integrated-review findings as the smallest independently verifiable follow-up tickets linked to the parent with native blocking edges where order matters using the recorded implementation selection with every rerun using the recorded review selection, runs no more than two automatic follow-up and final-review rounds with findings left after the second round gaining `needs-info` and returning to the user instead of an unlimited loop, and posts parent evidence with phase model configuration, review base, integrated commits, checks, planned and follow-up ticket links, recovery decisions, and final review outcome before closure. Existing adapters `plan-this` and `implement-this` keep their fixed-template bodies byte-for-byte unchanged and gain a narrow delegation path from an active `supervise-this` run. GitHub issues, native dependencies, evidence comments, and commits are the durable record; Agent Manager `list` is the live-state source and `.kilo/agent-manager.json` is never edited.

Why: Planning and implementation need different model cost and quality levels, and repeating manual worktree and spec management is slow and error-prone. A coordinator that validates model choices against the live catalog, asks once for missing input, confirms the exact resolved configuration, and reuses established adapter contracts avoids copying workflows, avoids stale allowlists, and keeps the supervisor focused on coordination and model routing rather than on reimplementing planning or ticket delivery. Local planning sessions match the publish-only nature of spec work, and a single recorded parent comment makes the run resumable from GitHub even when prior Agent Manager sessions are gone.

Consequences:

- The architecture index adds the `supervise-this` seam, its leaf doc, and this ADR.
- `plan-this` and `implement-this` declaration texts are extended to allow narrow delegation from an active `supervise-this` run without changing their fixed-template bodies.
- Registry-lane discovery uses `npx skills add RuralNative/RuralNative-SKILLS --skill supervise-this` with matching folder identity.
