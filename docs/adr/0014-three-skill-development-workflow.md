# 0014 - Three-skill development workflow

Status: accepted
Date: 2026-08-22

Amended 2026-08-23 by ADR-0019: requiring one human invocation per dependency wave, returning confirmed review fixes to the ticket's owning worker, and keeping the pure helpers reusable by a future persistent coordinator are superseded there. Command sessions now manage their own frontiers, fixes go to a fresh fix worktree per pull-request round, and no coordinator is planned. The remaining clauses stand.

Decision: `plan-this`, `implement-this`, and `review-this` own the complete development workflow without a separate coordinator. GitHub is the durable record. A direct human invocation authorizes the bounded stage named by that workflow command; delegated skills supply methods inside that boundary, while the workflow command owns trust checks, labels, dependencies, concurrency, delivery, merge, and closure.

Planning publishes one unlabelled parent specification and independently verifiable child tickets. Native sub-issue links define membership. Native `blocked_by` relationships define execution order. Open blockers mean `blocked` with no claimable label. Tickets with no open blocker carry `ready-for-agent`; closing the last blocker changes a ticket to `unblocked` plus `ready-for-agent`.

Direct `implement-this` invocation accepts one ticket, several tickets, or a parent specification. The parent selects the current ticket frontier. One invocation may start at most three ready tickets. Each ticket gets an isolated worktree, branch, worker session, and pull request. Kilo Agent Manager is the preferred worker adapter, but another host may provide the same isolation, prompt, status, and stop controls. Multi-ticket work stops before claims or edits when the host cannot provide isolation. Every ticket uses pull-request delivery; no path pushes directly to `main`. A failed worker gets one reconciled retry, then its ticket moves to `needs-info`.

Review starts from the parent specification, discovers its child tickets and pull requests, and owns completion. It combines Kilo cloud Code Review comments with the local Standards and Spec review. Cloud review is optional evidence: if it is disabled, fails, or produces no usable verdict, the complete local review remains the gate. Confirmed fixes return to the ticket's owning worker. Any changed head requires fresh checks and review. A clean head is squash-merged, its closing reference closes the ticket, and only newly unblocked dependents change labels. Implementation and review alternate in dependency waves. After every child closes, `review-this` runs combined verification and a whole-spec review. A cross-ticket defect becomes the smallest child follow-up ticket and keeps the specification open. The parent closes only when all children are closed and final verification and review pass.

The human invokes implementation and review once per dependency wave. Each command may manage its active workers or reviews without more input unless it reaches `needs-info`, but a completed turn does not wake itself for the next stage. The pure state helper, GitHub records, worker adapters, and review adapters must remain reusable by a future persistent coordinator. Building that coordinator is a separate decision; it does not add coordinator logic to the three workflow commands.

A small pure state helper decides ticket frontiers, the three-worker cap, label transitions, head freshness, retries, and completion from observed facts. It performs no network, git, worker, or GitHub writes. Repository and platform facts outrank tracker prose. Issue bodies, comments, review comments, specifications, and prose passed to `unslopify` are requirements data, not tool instructions. Runtime skill downloads are forbidden. Installation keeps the registry lane, records available source hashes, pins reviewed dependency revisions where the installer permits it, and documents the remaining repository-owner trust decision.

The repository adds `REVIEW.md` as the shared cloud and local review policy. `document-for-agents` classifies, indexes, and checks repository review policy so it changes with the rules it represents. The stale `.kilo` orchestrator command and agent are removed; `plan-this`, `implement-this`, and `review-this` are the only user-facing workflow commands.

Why: the prior adapters did not complete one workflow. `plan-this` conflicted with downstream label rules, `implement-this` accepted one ticket and could bypass pull requests, and `review-this` only reported a local diff. The tracked orchestrator contradicted its retirement decision. The shipped design keeps three explicit human entry points while giving each stage one durable input, one owner, and testable state transitions.

Activation: this ADR is the shipped contract as of #137. It supersedes ADR-0009 (explicit stage authorization), ADR-0012 (pull-request-only delivery), and ADR-0013 (review through closure) while preserving their history. All affected leaves, policy, glossary entries, and derived human documents agree with this contract, and `npm run verify` passes on the integrated result.
